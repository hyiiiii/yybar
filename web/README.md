# yybar 网站

用 GitHub 登录，接收 yybar App 上传的每日 token 用量和花费，做排行榜和积分；积分当筹码在 Bar 里打德州、在商场里买牌背牌面。顶栏四个图标入口：Bar（酒杯）、商场（购物车）、排行榜（领奖台）、成就（奖杯）。跑在 Cloudflare Workers 上，数据库是 D1（SQLite）。

## 结构

| 路径 | 内容 |
|---|---|
| `src/worker/` | 后端（Hono）：GitHub 登录、会话、上传令牌、用量接口、排行榜、牌桌接口 |
| `src/worker/table.ts` | 德州牌桌的 Durable Object：每张桌一个，WebSocket 推送、计时、筹码记账 |
| `src/shared/poker/` | 德州牌局逻辑（前后端共用）：发牌、下注、边池、比牌、机器人桌 |
| `src/client/` | 前端（React + Vite），构建到 `dist/` 由 Worker 的静态资源托管 |
| `migrations/` | D1 表结构 |
| `test/` | 上传校验、牌局逻辑的单元测试 |

## 本地开发

```sh
cd web
npm install
echo 'DEV_LOGIN=1' > .dev.vars        # 本地免 GitHub 登录：/auth/dev-login?login=alice
npm run db:migrate:local
npm run dev                            # http://localhost:8787
npm test && npm run typecheck
```

本地试多人德州：每个窗口要是不同的登录，用无痕窗口或不同浏览器分别打开
`http://localhost:8787/auth/dev-login?login=alice&next=/table/1002`（把 alice 换成 bob、carol…）。
本地假账号第一次登录会送 20,000 筹码。

## 部署到 Cloudflare

1. 在 GitHub 新建 OAuth App（Settings → Developer settings → OAuth Apps）：
   - Homepage URL：网站地址，例如 `https://yybar.<你的子域>.workers.dev`
   - Authorization callback URL：`<网站地址>/auth/github/callback`
2. 创建数据库，把返回的 `database_id` 填进 `wrangler.jsonc`，同时把 `APP_URL` 改成网站地址：
   ```sh
   npx wrangler login
   npx wrangler d1 create yybar
   ```
3. 设置机密：
   ```sh
   npx wrangler secret put GITHUB_CLIENT_ID
   npx wrangler secret put GITHUB_CLIENT_SECRET
   ```
4. `npm run deploy`（构建前端、执行迁移、发布 Worker）。

线上不要设置 `DEV_LOGIN`。

## App 上传接口

所有请求带 `Authorization: Bearer <上传令牌>`。令牌由 App 走连接流程获得（网站「我的」页不再列令牌，改成「上传记录」：最近收到的 10 天，每天的上传时间、token、花费和换得的筹码，`GET /api/me` 的 `uploads`）。

**连接流程**：App 打开 `<网站>/connect?state=<随机串>`，用户登录并点「授权」后，浏览器跳到
`yybar://connect?token=<令牌>&state=<原样返回>`，App 校验 state 后保存令牌。

`GET /api/v1/whoami` → `{ "user": { "login", "name", "avatarUrl" } }`，用来确认令牌有效，App 拿头像显示在左下角。

`GET /api/v1/usage/days` → `{ "days": ["2026-10-20", …], "uploads": [{ "day": "2026-10-20", "app": "claude", "total": 123456, "costMicro": 4560000 }, …] }`：已经上传过的日期，和每一天哪几个服务传过、传了多少（`total` 是 token 总数，Gemini 是回答次数；`costMicro` 是按服务端价格算的花费）；App 启动、连上、每次上传前用 `uploads` 补本地的「已上传」标记和量，本机某天的量比 `total` 多就再传（旧版 App 只认 `days`）。

`POST /api/v1/usage`

```json
{
  "days": [
    {
      "day": "2026-10-17",
      "entries": [
        { "app": "claude", "model": "claude-sonnet-4.5", "inputTokens": 1200, "outputTokens": 3400,
          "cacheReadTokens": 560000, "cacheCreationTokens": 7800, "costUSD": "12.345678" },
        { "app": "gemini", "model": "gemini", "answers": 42 }
      ]
    }
  ]
}
```

- 字段与 App 里的 `UsageBucket` 一致；`day` 是用户本地日期，`costUSD` 用十进制字符串。
- **花费由服务端算**：App 里可以自己改模型价格，所以不用 App 报的 `costUSD`，而是按服务端的价格表 `model_prices`（迁移 `0012_model_prices.sql`，初始值和 App 内置的官方价一致；美元 / 百万 token，token 数 × 单价正好是微美元）和 token 数现算，存进 `daily_usage.cost_micro`；App 报的另存在 `client_cost_micro`，只作对照。查价前把模型名归一化（小写，去掉 `openai/`、`xai/` 前缀、`@` 版本和日期后缀，`src/shared/pricing.ts`），先找完全一样的，再找最长的 `*` 前缀。Grok 那一行是 `grok-*`、`billed = 1`：App 读的是 xAI 账单里的实际扣费，收它但不超过按 Grok 4 公开价（$3 / $15 / 缓存 $0.75）算的数。表里没有的模型、Grok Bot（只有合计 token）、Gemini（只有回答次数）花费是 0。迁移时已经按这张表重算了以前上传的花费（OpenAI 超过 272K 上下文的阶梯价、claude.ai 云端用量的接口金额都按表价算，总共少了约 $28）。以后改价直接改这张表；`GET /api/prices` 返回整张表。`app` 是 `codex / claude / grok / grokBot / gemini / agy` 之一（和 App 的 `UsageApp` 一致）。Gemini 没有 token 和花费，只传 `answers`（那天的回答次数），不换筹码；其他字段缺省按 0。
- 每个 `day` 是那天的完整汇总，**每一天的每个服务只记一份，量变多了才换**：收下后把 (日期, 服务) 和这次的量（`total`：token 总数，Gemini 是回答次数）记进 `usage_uploads`（迁移 `0007_usage_uploads.sql`，`0009_usage_apps.sql` 改成按服务记，以前标过的日子当作 Codex / Claude / Grok 都传过了；`0015_upload_totals.sql` 加 `total`，以前的按已存的用量补上）。以后再传同一天同一个服务：量比记下的多（比如 App 新加了一个 Codex 目录，找到了另一个账号那天的会话）就整份换成新的、筹码跟着重算；一样多或更少就跳过、不改也不加。所以重复上传、换台电脑上传都不会叠加筹码（几台电脑各有一部分时取量最多的那份）；App 以后新支持的服务，已经传过的日子还能补上。删旧的、写新的、改标记在同一个事务里，条件都按标记里记的量判断，并发的两次上传不会叠加，量少的不会盖掉量多的。返回 `{ "ok": true, "accepted": [这次有新内容收下或换掉的日期], "skipped": [所有服务都没变、整天跳过的日期] }`。
- App 只传今天以前（本地日期）、已经过完的天；服务端只收不晚于 UTC 今天的日期（任何时区的「本地昨天」都不晚于 UTC 今天）。
- 限制：一次最多 120 天、每天 300 条；日期不早于 2023-01-01；单日总花费（App 报的或按价格表算的）超过 $5000 整个请求拒收（422）。

`PUT /api/v1/accounts`：这台设备上各服务账号的订阅，个人主页 @ 后面那一排用（2026-10-28 起）。

```json
{ "device": "0f8e2a4c-1b3d-4e5f-8a9b-0c1d2e3f4a5b", "accounts": [ { "app": "codex", "account": "b3a1bda91f071c46", "plan": "pro" }, { "app": "gemini", "account": "…", "plan": "Google AI Pro" } ] }
```

- 一个账号一条。`account` 是 App 端算的「`yybar:<服务>:<账号（小写邮箱等）>`」SHA-256 前 16 位十六进制，不传邮箱；Mac 和 Windows 算法一样，同一个账号在几台设备上传，网站认得出是同一个。`plan` 原样传 App 读到的套餐名（≤ 40 字，不收控制字符和尖括号）。Gemini App 和 Antigravity 是同一份 Google 订阅，App 都记成 `gemini`。
- `device` 是这台电脑固定的 UUID（Mac 存在设置 `yybar.settings.webDevice`，Windows 存在 `%APPDATA%\yybar\device-id`，第一次传订阅时生成）。
- 存在 `user_accounts`（迁移 `0013_user_accounts.sql`，`0014_account_devices.sql` 加 `device`）：每台设备一份，每次整份替换——带 `device` 时换掉这台设备上次传的，不管当时用的哪个上传令牌（重新连接网站会拿到新令牌，以前按令牌替换，旧令牌没撤销的话它传过的旧订阅一直留在主页上），并顺手清掉旧版 App 不带 `device` 传的行；不带 `device`（旧版 App）时按令牌替换。显示时几台设备按（服务, 账号）去重、同一账号取最近一次传的套餐，再按（服务, 套餐）计数；撤销了的令牌、90 天没再传的设备不算（`src/worker/accounts.ts`）。
- 订阅随用量一起上传：App 每次上传（一键 / 自动，不管有没有新的天）都先把当前的订阅整份 PUT 上来，没传成功不影响用量，下次上传再传。一次最多 50 个账号；返回 `{ "ok": true, "count": n }`。

## 排行榜

- 用图标切换两种排法，只列在「我的」里打开了「在排行榜和公开主页上显示我」的人。
- 燃烧 token（火苗）：按时间段（昨天 / 7 天 / 30 天 / 总榜；App 只传已经过完的天，所以是昨天不是今天）内的 token 数排名，每行带最常用的模型和这些 token 的花费；第一名最右边的小按钮切换按 token 数还是按花费排。`GET /api/leaderboard?by=tokens&range=yesterday|7d|30d|all&sort=tokens|cost`（`today` 还收，留给旧页面）。
- 财富（筹码）：按筹码余额排名（坐在桌上的筹码不算，离桌退回后才算）。每行还有「今日输赢」：今天（UTC）每手「赢到的 − 投进去的」加起来，赢绿输红，今天没打是一道横线；记在 `poker_daily`（迁移 `0008_poker_daily.sql`，每手结束和手数统计一起写）。第一名右边的小按钮在按余额排和按今日输赢排之间切换（今天打过的排前面）。`GET /api/leaderboard?by=wealth&sort=balance|today`。

- 「我的」和公开的个人页（`/u/<login>`）一样：三张总数卡片（「总花费」旁边一个小问号，点开是服务端的模型价格表，按厂商分组，`src/client/Prices.tsx`），下面照 yybar App 统计页做（`src/client/UsageCharts.tsx`）。
- 最上面一排服务筛选：全部 / Codex / Claude / Grok / Grok Bot / Gemini / Antigravity（只列有用量的），按钮上是各家的标（Codex、Claude、Grok、Gemini 和牌面花色同一套，染服务识别色；Grok Bot、Antigravity 用 App 里的标）；下面三块都跟着筛选走。
- 拆开 / 合并和 App 里一样：Grok + Grok Bot、Gemini + Antigravity 两两一组，默认合并成一个按钮（两个标并排），后面跟一个只有图标的小按钮（分叉 / 汇合箭头），两组各拆各的；每次打开都是合并的，不记。切换时留下的按钮滑到新位置、新出来的放大淡入、小图标转半圈换过去，每日用量里同组的两段渐变成同一个颜色；选着的服务跟着换过去（拆开选前一家，合并选整组）。一组里只用过一家就只显示那一家，不带小按钮。
- 只选 Gemini 时没有 token 和花费，三块都改看回答次数：Token 活动变「回答活动」，每日用量的柱是每天回答多少次，模型明细显示「N 次回答」、其他列「—」。其他时候 Gemini 的回答次数写在每日用量的浮层里。
- Token 活动（放在最上面）：四格汇总（累计 Token 数、单日峰值、最长连续天数、当前连续天数），下面最近 53 周的格子，每列一周（周一开头）。每天 = 热力格，按这段时间有用量的日子的 25% / 50% / 75% 分位分四档，全部时用暖色，只选一个服务时用它的识别色；每周 / 累计总量 = 每列从下往上按比例填。悬停有深色浮层。
- 每日用量：近 30 天每天一根柱，按服务（合并时按组）叠起来，标题旁边是日均（图上一道虚线），右上角是服务的标和费用 / Tokens 切换，悬停看当天每个服务多少。
- 模型明细：昨天 / 7 天 / 30 天 / 全部切换，每个模型的输入、输出、缓存读取、缓存写入、合计、费用，点表头排序，默认按合计；这段时间合计最多的模型后面一团蹦着的小火苗。Codex / Grok 不单独记缓存写入，显示「—」。
- `GET /api/me`、`GET /api/users/<login>`：`models` 是最近 30 天每天每个模型一行（`day / app / model / input / output / cache_read / cache_write / cost_micro`），网页按时间段、服务自己加；`modelsAll` 是所有日子每个模型的合计（没有 `day`），模型明细选「全部」时用；`activity` 是最近 378 天每天每个服务的 token 合计；三处都带 `answers`（Gemini 的回答次数）。

## 商场

- 用筹码买东西，款式、价格、中英文名都在 `src/shared/cosmetics.ts`。名字都是一眼看得出在玩哪副牌的梗（Bicyle、Tally-Hoo、Purr、Daybrake），不是正版；牌背中英文界面都用英文名。
- 价格：牌背、牌面 $3,000，Daybrake 牌背和鎏金牌面 $10,000；表情、道具都是 $500。
- 牌背（7 款）：你的暗牌在同桌所有人眼里都是这一款；你自己屏幕上桌面中间的背面牌也用它。
- 牌面（5 款）：你的牌翻开时用这一款，同桌的人都看得到；公共牌在你屏幕上也用它。
- 牌背、牌面换了之后下次连上牌桌时生效。样式在 `styles.css` 的 `.back-<款式>` / `.card.face-<款式>`。
- 表情（9 个，前 4 个默认就有）：Claude 像素小人，坐在桌上时点手牌下面的笑脸发给全桌，在那个人头上冒一下。两次至少隔 1.5 秒。
- 道具（按个数买，用掉就少一个，存在 `user_items`）：
  - 加时卡：轮到你时多 10 秒，每次行动一张。
  - 偷偷看：一手结束后看别人没亮出来的底牌（弃了的也算）。只有你看得到，发牌员会告诉全桌「某某用了偷偷看」。
  - 发发看：一手提前结束时，按发牌顺序（先烧一张）看还没翻出来的公共牌。同样只有你看得到、全桌会被告知。
  - 三个道具和表情按钮都在你手牌下面。牌桌先检查能不能用，再扣库存，再生效；扣库存时局面变了就退回去。
- 买牌背、牌面、表情记在 `points_ledger`（`reason = 'shop'`，`ref = shop:<用户>:<种类>:<款式>`，同一款不会扣两次）；买道具的扣款和加库存在同一个事务里。正在用的款式在 `users.card_back` / `users.card_face`（迁移 `0004_cosmetics.sql`）。
- 接口：`GET /api/shop`、`POST /api/shop/buy {"kind":"back|face|emote|item","id":…}`、`POST /api/shop/equip {…}`；`GET /api/me` 带 `look`、`items`、`emotes`。牌桌消息：`{"t":"item","item":"timecard|peek|runout"}`、`{"t":"emote","id":…}`。

## 扔番茄、送玫瑰

- 牌桌上点别人的头像，卡片下面一排三个按钮：扔一个番茄 $100、连扔五个番茄 $500、送一支玫瑰 $100。登录了就能扔，坐着的人从自己座位扔，旁观的人从桌子下边扔；不能扔给自己，同一个人两次至少隔 2 秒。
- 番茄划一道弧线飞过去，砸在头像上糊成一摊，过两秒滑落消失；玫瑰轻轻转着飞过去落在头像上，冒几颗小心心往上飘，然后淡掉（`src/client/Throw.tsx`，Web Animations 直接播，不走 React 状态；元素挂上页面前先写好起点位置，不会在左上角闪一下；落地动画从飞行的最后一帧接着播——Web Animations 不会把动画位置写回 style，从 style 起步会先跳回起点再飞过来；番茄那一摊的缩放、下滑都写在同一个 `transform` 里，不用单独的 `scale` / `translate` 属性，那两个是绕整层左上角算的）。
- 牌桌先检查能不能扔，再从账户扣钱（`points_ledger`，`reason = 'tomato' | 'rose'`，余额判断和扣款同一条语句），扣成功才扔；扔不了就退回。牌桌消息 `{"t":"throw","item":"tomato|rose","seat":…,"n":1|5}`（玫瑰只能 1），全桌收到 `kind: "throw"`、`what: "tomato:5"` 这样的事件（`from` 是扔的人的座位，旁观是 null）。

- 除了牌局的 4 个，都在打开网站（`/api/me`）和成就页时按用量、流水、订阅自动检查；大赢家、葫芦、四条、同花顺由牌桌在一手结束时记下。解锁记在 `user_achievements`（`claimed_at` 为空 = 还没领，迁移 `0010_achievement_claims.sql`；以前解锁的当时已经自动发过奖励，都当作领过），领取时奖励记进 `points_ledger`（`reason = 'achievement'`，`ref = ach:<用户>:<成就>`），只在这一行还没领时写、ref 也去重，连点不会重复发。戴着的徽章在 `users.badges`（JSON 数组，迁移 `0005_achievements.sql`）。
- 接口：`GET /api/achievements`（成就、进度、每个的 `unlockedAt` / `claimedAt`、正在戴的徽章）、`POST /api/achievements/claim {"id": …}`（不带 id 就把能领的全领了，回 `amount`）、`POST /api/achievements/wear {"id": …, "on": true | false}`。

## 积分

- 筹码 = 累计记录花费（服务端按价格表算的，$1 = 1 筹码，向下取整；2026-10-22 之前是 $1 = 100），随上传实时计算。
- 德州的买入和离桌退回记在 `points_ledger`，余额 = 花费积分 + 流水合计。
- 积分只能这样获得，不能充值、购买或兑现。

## 德州牌桌

- 手机（≤ 600px）：别人的牌背面不摆，翻开的（摊牌、亮牌、偷偷看）摆出来，上面一排和左右两边的人摆在名牌下面，下面一排摆在头像上方；点头像弹出的卡片从靠屏幕边的那一侧展开，不再伸出屏幕（2026-10-28 前别人的牌在手机上一律不显示，摊牌也看不到）。
- 无限注德州，每桌 6 个座位。筹码按美元显示：1 个筹码记作 $1（盲注 5/10 显示成 $5/$10）。桌子存在 D1 的 `poker_tables`，默认 4 张（`migrations/0006_fewer_tables.sql`）：#1000 机器人桌 $1/$2，#1001 $1/$2、#1002 $2/$5、#1003 $5/$10。打开牌桌页先看到机器人桌，大厅里它的桌号画成机器人图标。
- 每张桌一个 Durable Object（`PokerTable`，按桌号取），牌局完全在服务端跑：洗牌用 `crypto.getRandomValues`，别人的底牌在摊牌前不会发到浏览器。
- 连接：`GET /api/tables/<桌号>/ws` 升级为 WebSocket。带登录 cookie 可以入座，没登录只能旁观；只接受本站页面发起的连接。
  - 浏览器发：`{"t":"hold","seat":0-5}`（点空位先占座）、`{"t":"release"}`（不坐了）、`{"t":"sit","seat":0-5,"buyIn":带入筹码}`（不带 `buyIn` 按 100 个大盲）、`{"t":"show","which":0|1|2}`（别人都弃牌赢下时亮第一张 / 第二张 / 两张）、`{"t":"leave"}`、`{"t":"act","action":"fold|check|call|raise","amount":加注到多少}`。
  - 服务端推：`{"t":"state","view":{…}}`（每人看到自己的视角，字段见 `src/shared/poker/types.ts`）、`{"t":"error","msg":"…"}`、`{"t":"closed"}`（玩家开的桌没人了，已收掉）。
- 占座：点空位先占 10 秒，牌子上写「买入中…」，头像变灰，外面一圈橙色倒计时，走过的部分变白；别人抢不走，10 秒内没坐下就放开。
- 输光再买入：在一张桌上筹码输光，下一手开始前站起来，但座位替你占 10 秒（同样是「买入中…」），余额够最低买入就自动弹出买入面板，可以原位再坐下；余额不够直接放开。
- 带入：点空位后用滑杆选带多少入座，40～200 个大盲（不超过余额），默认 100 个。余额判断和扣款是同一条 SQL，同时在几张桌入座也不会扣成负数。
- 离桌：不在牌局里马上结算；牌局中离桌先弃牌，这手结束后把剩余筹码退回余额。买入和退回都记在 `points_ledger`（`buyin` / `cashout`），按 `ref` 去重，写失败会存着重试。
- 计时：每次行动 15 秒，轮到谁，谁的头像外圈有一圈绿条慢慢缩短；超时能过牌就过牌、否则弃牌；连续两次超时自动离桌。掉线的人轮到时只等 5 秒，掉线超过 1 分钟，下一手开始前自动离桌。
- 机器人桌：三个机器人 bot-C、bot-G、bot-D 坐 1、3、5 号（隔一个座位，不挨着），有没有真人都一直打，真人可以坐剩下的座位一起玩。机器人带 $100（50 个大盲）；输光了（不够一个大盲）原位再带 $100，赢到 $200 以上就离桌歇一手，再带 $100 回来，座位被真人占了就找一个两边不是机器人的空位，自己的座位空出来后，下一手开始前坐回去。机器人每次想 1.5～3 秒（模拟下来一手平均约 29 秒）。机器人的筹码不进任何账户。
- 机器人桌没人看的时候不真跑：桌上没有真人、也没人连着时，Durable Object 记下停手的时刻、不再排闹钟；有人打开这张桌（或闹钟响了）时，先把停手这段时间按原来的节奏一手一手补打完（`TableRoom.resume`），再从现在接着打，所以手数、筹码、谁在歇着都像一直在打一样。真打最多 500 手（几十毫秒），停得更久的，剩下的时间只把手数往前加（一手按 29 秒算）。这样不用每一两秒醒一次：全天真跑的话，免费额度每天 10 万行写入撑不住（实测每秒约 0.63 次闹钟，每次至少写 2 行）。
- 桌号重新用上（删掉的桌号又被玩家开出来）时，牌桌按 `poker_tables.created_at` 认出旧存档，旧存档里没人就从头开。
- 座位：圆盘里是 GitHub 头像（没有头像用名字首字母；机器人桌的 bot-C、bot-G、bot-D 用 `public/bots/` 里的 Q 版头像，点机器人的头像显示它今天（UTC 日期，和全站的「今天」一致）每手输赢加起来赢了或输了多少，补打的手也算；别的机器人画机器人图标），下面的小牌子上是位置（BTN / SB / BB…）、名字和余额，刚才的动作是头上的小标签；进入下一条街时服务端把它挪到 `prev`（最后一个人的动作和换街是同一步，不这样网页根本收不到），网页一直挂着，直到这个人在新的一条街再行动；每次行动标签都重新弹一下。入座后桌子转起来把你转到下方，座位沿着桌边一格一格走过去；庄家按钮换庄时也是滑过去的。左右两个座位的下注放在桌面里。
- 都全下（没人能再行动）时，大家的牌在各自座位上翻开（不丢到桌面上，丢牌只用在赢了没摊牌时自己选择亮牌），剩下的公共牌一条街一条街发，每条隔 2.4 秒，不会一下子五张全出来。
- 结算：几个人一样大就平分；全下的人只能赢他跟得起的那一份（主池），多出来的是边池，留给其他人比。只赢到边池的人 WIN 牌子上写「边池」。
- 结算：没人跟的下注（投入最多的人比第二多的人多出来的部分）先原样退回，不算赢，再按主池、边池分。
- 赢家：头像一圈金光，牌子上是 WIN、赢了多少和名字，牌型用金色标签写在头顶。别人都弃牌赢下时，点自己的一张牌就把它正面朝上丢到桌面上，再点一张再丢一张（或「两张都亮」）。中途弃牌的人牌留在自己手里（变暗，别人看不到），一手结束后同样可以点一张或「两张都亮」，牌在原地翻过来给全桌看。一手结束后摊牌停 9 秒、别人都弃牌赢下停 5 秒再开下一手。摊牌时别人的牌翻开有翻牌动画。轮到你行动时自己的牌有一圈光晕。离桌要再点一次确认。
- 多桌：可以同时坐几张桌。坐着的桌记在 `poker_seats`（牌桌实时回写），`GET /api/tables` 登录时带上 `mine`；前端在后台连着这些桌，不算掉线，坐着时不能开新桌。轮到你行动时手机上震动（`navigator.vibrate`，iOS Safari 不支持）。
- 骰子（招牌右边，原来的铃铛）：点一下掷一个 0–100 的数。登录了由牌桌（服务端，`crypto` 取随机）出数，牌桌消息 `{"t":"roll"}`，全桌收到 `kind: "roll"`、`what: "57"` 的事件；坐着的人点数从头像上冒出来（先乱跳一小会儿再停住），旁观的人由发牌员说「xx 掷出了 57 点」；同一个人两次至少隔 2 秒。没登录只在自己这里掷，发牌员告诉你点数。
- 发牌员平时不说话，会眨眼、东张西望、招手、洗牌、蹦一下；登录后它冒个气泡打招呼（「又开工了，hyi」），几秒后消失。
- 加注：滑杆在最小加注和全下之间按小盲取整，旁边有 2.5x / 3x、半池、底池几个快捷额度。
- 布告栏（标题写 Notice Board）：列出现在开着的桌（机器人桌画成机器人标）、盲注和桌上人数（`在座/6`，机器人也算，机器人桌没人时是 3/6；有人坐着亮绿点，坐满亮橙点），当前这桌高亮，点一行去那张桌。宽屏（≥1400px）钉在牌桌左边的空白里（顶上一颗图钉）；窄屏是操作区下面的一张小告示。悬停时另外写连着这张桌的真人有几个（在座的和旁观的，同一个账号开几个页面算一个，没登录的每个连接算一个），牌桌在有人连上 / 断开时和在座人数一起写回 `poker_tables.online`（迁移 `0011_table_online.sql`），`GET /api/tables` 带上；页面开着时每 30 秒刷新一次，切回标签页时马上刷新。
- 布局：招牌左边是切桌和按桌号找桌，右边是骰子、音效和开桌，布告栏见上；桌子的大小跟着窗口高度走，切桌、开桌、出牌都不用往下滚。窗口太矮放不下时，下面的操作区贴在窗口底部。
- 开桌：点招牌右边的加号，选盲注（$1/$2、$2/$5、$5/$10、$10/$20、$25/$50、$50/$100、$100/$200、$200/$400）和带入，开好后自动入座。接口是 `POST /api/tables {"blinds":[小盲,大盲]}`，桌号接在最后；坐在任何一张桌上时不能开新桌（按 `poker_seats` 判断），每人最多同时开 3 张。`GET /api/tables` 列出所有桌、在座人数和是不是玩家开的（`temporary`）。
- 空桌收掉：玩家开的桌没有真人坐着（离桌的筹码也都退回了）超过 30 秒，牌桌就从大厅删掉、存档清空，还连着的人会被送回默认桌；开了却一直没人连上去的桌，2 分钟后在 `GET /api/tables` 时顺手清掉。默认的 4 张桌不会收。
- 预览版（`npm run build:demo`）没有服务端，同一套牌局逻辑直接在浏览器里跑，其他座位是机器人；预览里自己开的桌放三个机器人陪打。
- 过渡动画：下注的筹码从座位推出来，弃牌时两张牌往桌心收走，动作文字和底池数字轻轻弹一下；系统设置了减少动态效果时不播。

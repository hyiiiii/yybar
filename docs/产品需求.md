# yybar 产品需求

> 描述当前已交付版本的功能范围与边界。新需求迭代时以本文为准；与代码不一致以代码为准并同步回这里。

---

## 0. 产品定位

- **形态**：常驻菜单栏的小工具（Accessory App，不占 Dock）。
- **平台**：macOS 14 Sonoma+（依赖 SwiftUI `MenuBarExtra(.window)`、`@Observable`、`SMAppService`）。
- **设计**：以 macOS HIG 为底座，关键信息层（百分比、进度、KPI、HUD）按设计稿落地自绘组件；非关键层（Picker / Toggle / DatePicker / TabView / Material）全部用系统默认。
- **一句话价值**：装上它 → 不打开 CLI 也能随时看到 Codex / Claude Code / Grok 还剩多少额度、今天和本周花了多少钱。

## 1. 账号自动识别

- 启动时扫描本机已有的 Codex / Claude Code / Grok 凭据：
  - Codex：`~/.codex/auth.json`（OAuth 模式，解析 JWT 拿邮箱 / plan / accountId）。
  - Claude：先读 `~/.claude/.credentials.json`；不存在则读 macOS Keychain 通用密码项 `Claude Code-credentials`（service name）。邮箱兜底从 `~/.claude.json` 顶层 `oauthAccount.emailAddress` 读取。
  - Grok：读 `~/.grok/auth.json` 中的 first-party xAI 账号（`https://auth.x.ai::…`），用其中的 API key 请求云端额度。过期时委托已安装的 `grok models` 只读命令续期，不发起对话。
  - Gemini App：复用 Chrome 当前个人资料的 Google 登录，读取 Gemini Apps 网页的当前（5 小时）与每周额度及重置时间。需要 Chrome 与 Gemini App 使用同一账号；首次由 yybar 请求钥匙串「Chrome Safe Storage」访问。查询额度(定时刷新最快 15 分钟一次，手动刷新不限;2026-10-28 起，此前 2 分钟一次——同一份 Google 登录被 Chrome 之外的程序频繁使用，Google 可能当成会话被盗用，让 Chrome 重新登录 / 验证)，并每 30 分钟最多读一次近期会话的回答(见下方「用量统计」的回答次数)，只保存 天 + 模型 + 次数和回答 / 会话 ID 的摘要，不保存正文、标题或会话 ID，不发送推理、不刷新登录；拒绝钥匙串后仅手动刷新重试；Google 拒绝了这份登录(跳去登录页、401 / 403、要求网页验证)后，定时刷新 6 小时内不再拿同一份登录请求，Chrome 重新登录或通过验证后自动恢复，手动刷新照常请求。与 Antigravity 独立显示、缓存、退避和记录额度变化。
  - Antigravity / agy：通过本机 agy CLI 的只读命令 `agy -p /usage --output-format json` 读取 Gemini 模型与 Claude·GPT 两个池子，各有 5 小时和每周限制，全部显示在 Antigravity 下。agy CLI 或 Gemini.app 安装检测沿用现有设置。
  - Grok Bot（额度与按天模型用量）：Grok Bot 桌面 App 用 Cursor 账号登录，每周额度来自 `api2.cursor.sh` 的 `DashboardService/GetSandUsageStatus`（App 自己「设置 → 用量与账单」用的同一接口）。App 的登录 token 用 Electron safeStorage 加密存放，yybar 用钥匙串「Grok Bot Safe Storage」里的口令解密后只读使用（不刷新、不写回、不记日志）；首次读取 macOS 会弹钥匙串窗口(问的是 yybar 本身，只信任 yybar),允许一次后 yybar 把解密密钥存进自己只有本用户可读的文件，之后(包括重新构建安装后)不再读钥匙串、不再弹窗;Grok Bot 重装导致密钥失效时才会再问一次。拒绝后定时刷新不再弹窗，手动刷新时再问。token 过期时提示打开 Grok Bot app 让它自己续期。解不出 token 时，钥匙串被拒绝 / 取消和「解密后找不到 token」分开提示，后者附一句安全诊断：文件格式、找到几个加密块、解开几个、在哪些键路径下（像账号的键名打码，不显示任何内容、token 或口令）。跟其他额度一起刷新，剩余减少时菜单栏图标呼吸。本机有 `/Applications/Grok Bot.app` 时默认启用（含菜单栏、悬浮窗）。
  - 用量统计：Gemini / Antigravity 读本机 agy CLI 的会话库（只读每次调用的 token 数、模型和时间，不读对话内容），按工具归属：agy 里的所有调用（包括 Gemini 3.8 Flash 等 Gemini 模型）都记到 Antigravity；Gemini App 本机没有对话记录、Google 也不给 token 数，2026-10-21 起改按回答次数统计：每 30 分钟最多读一次 Gemini 网页会话列表(最近 20 个普通 + 置顶会话)，只读更新时间比上次新的会话(新的优先，每次最多 6 个，其余下次再读)，每个取最近 30 轮(30 轮全是没记过的新回答时再补读最近 200 轮，免得漏算)，按回答 ID 去重；会话没给更新时间时，没有时间戳的回答记在当天，且下次照样读这个会话，记 天 + 模型 + 次数(时间取这一轮自己的时间戳，取不到用会话更新时间)。从开始记录起才有数据，第一次读到的会话只补最近 30 轮；按 Google 账号分开记录。服务筛选只选 Gemini 时，概览 KPI 换成 回答次数(环比 / 对比基准)/ 最常用模型 / 用过的模型，「今天」面板、每日用量图、Token 活动(标题改为「回答活动」)都按回答次数，费用 / Tokens 切换换成「回答次数」标签；其他筛选下 Gemini 也一律按次数、不计入费用和 Tokens(KPI 卡不含 Gemini);「今天」面板里 Gemini · Antigravity 和 Grok · Grok Bot 一样可合并 / 拆开：合并时一整条，条形只算 Antigravity(和其他行同一比例尺)，右侧写「Antigravity 数值 · Gemini 次数 / 均 … · …」(这时所有行的数值列一起加宽到 200pt,条形右端仍对齐)，悬停说明 Gemini 不计入条形;拆开时 Gemini 那条写「N 次 / 均 M 次」、各用自己的比例尺。Gemini 不参与其他行的比例尺和底部「为它的 X%」;每日用量柱子里不画 Gemini:柱子下方(0 线以下)留一条窄道，有回答的那天放一颗 Gemini 小星，回答越多星越大(面积按当天次数 / 这段时间单日最多，7~13pt)，随柱子一起淡入，图例只写服务名，悬停浮层写当天次数;模型明细里 Gemini 各模型一行，模型名后写「N 次回答」,token / 费用列为「—」;设置 · 账号里 Gemini 的「查看额度」浮层底部写「今日 N 次 · 本周 N 次」(其他服务这里是花费)。额度也按工具归属：Antigravity 格子同时显示 agy 的两个池子（Gemini 5H / Gemini WK / Claude·GPT 5H / Claude·GPT WK，注「数据来自 agy」），菜单栏、悬浮窗只有一个数字时取两个池里剩余最少的那个，任一池下降都会呼吸（呼吸用彩虹色 logo）。Gemini 格子是 Gemini.app 自己的额度：和 agy 的池子不是同一份（在 Gemini.app 里用 Gemini 4 不会让 agy 的额度变化），通过 Gemini Apps 网页额度接口读取，菜单栏 / 悬浮窗正常显示 Gemini。Grok Bot 账单按天、模型分类提供总 token，尚无输入／输出／缓存拆分（暂列在输入列，附说明）；查询限定 clientType=grok-bot、products=[sand]。费用仅展示接口返回的正数金额，其余显示「—」，不因模型有公开价格而显示 $0。额度比例不换算成 token。
- 不做 App 内登录流程。前提：用户已经在终端跑过 `codex login` / `claude` / `grok login`（Gemini App 需 Chrome 已登录同一 Google 账号；agy 需自己的 Google 登录）。
- 用户可在「设置 → 账号」勾选要显示的服务；关闭后该服务在菜单栏、Popover、悬浮窗、统计中均不出现，也不查询其 API。
- 首次启动若不存在 `~/.claude/.credentials.json`，且尚未提示过，会先弹一次说明性 Alert（"接下来 macOS 会弹 Keychain 授权窗口，请选择始终允许"），再触发系统 Keychain 弹窗。

## 2. 菜单栏标签

- 标签是模板图像（template NSImage），自适应深浅菜单栏。
- 顺序固定：**Codex → Claude → Grok → Grok Bot → Gemini → agy**。
- 每段为 `<服务 logo>  <百分比>`：
  - Logo 用项目内置的 `codex.svg` / `claude.svg` / `grok.svg`（不是 SF Symbol，保留服务的颜色辨识度——菜单栏会做模板化变灰）。
  - 百分比用 `monospacedDigit`。
  - Grok 没有 5 小时窗口，菜单栏始终显示其云端当前计费周期剩余百分比；Grok Bot 同样只有周额度。Gemini / agy 和 Codex / Claude 一样按 5H / WK 设置显示。
  - Grok Bot / Gemini / agy 的 logo 是项目内置的占位矢量图（`grokBot.svg` / `gemini.svg` / `agy.svg`，不是官方 logo，后续可替换）。
- 设置项：
  - 显示哪个服务（Codex / Claude / Grok / Grok Bot / Gemini / agy，可分别开关）。
  - 显示哪个额度窗口：5 小时 / 周窗口 / 两者（`5h/1w` 斜杠拼接）；该选项只作用于 Codex / Claude。
- 都关闭时仍保留一个占位 logo，避免菜单栏完全消失。
- 使用中呼吸（Codex 呼吸色：深色栏 #48484A、浅色栏 #AEAEB2）：某服务的本地会话日志在最近 30 秒内有写入时，菜单栏里该服务的 logo 在原色和识别色之间呼吸闪烁（1.6s 一周期），写入停止后自动停止。等待审批时（日志最后是还没有结果的工具调用，且 3 秒没有新写入）图标保持识别色不呼吸，有新写入后恢复；最多保持 30 分钟，由设置 · 显示「等待审批保持颜色」单独控制（默认开）。长时间运行且不写日志的工具也会被当成等待审批。设置 → 显示 →「使用中图标呼吸」可关闭，默认开启。Antigravity(agy CLI)没有 `.jsonl`,看它的会话库(`~/.gemini/antigravity-cli/conversations/*.db` 和 `-wal`)最近 30 秒有没有被修改(只看修改事件，不打开读内容),额度下降的呼吸仍保留作最后兜底。
- 用 hook 驱动呼吸（2026-10-20，设置 → 显示 → 菜单栏「用 hook 驱动呼吸」，默认关）：打开后给 Codex（`~/.codex/hooks.json`）、Claude Code（`~/.claude/settings.json`）、Grok（新建 `~/.grok/hooks/yybar.json`）、agy（`~/.gemini/config/hooks.json` 里的 `yybar-activity`）挂上 yybar 自己的 hook，只追加 yybar 的条目，用户原有 hook 不动，改前备份原文件；关掉只删 yybar 的条目。hook 脚本只把「哪个 CLI 的哪个会话现在是什么状态」和时间写到 `~/Library/Application Support/yybar/activity/`，不读对话内容。效果：提问、调用工具时立刻呼吸；请求审批（Codex / Claude 的 PermissionRequest，Claude / Grok 的 permission_prompt 通知）时立刻保持识别色；回答结束 / 会话结束 / Grok 取消时立刻停（不再拖 30 秒）；Claude、Codex 被 Ctrl-C 中断不触发 Stop hook，仍从会话日志里识别中断。Codex 回合已经写下 task_complete 但没有 Stop 时，同样立刻停止呼吸，不再干等 15 分钟。2026-10-22:额度用完(5H 或 WK 剩 0、还没到重置时间)的服务不呼吸——这时在 CLI 里发消息会立刻报额度不足，回合根本没开始，日志不写、结束 hook 也不触发，以前会一直停在「使用中」，每发一次闪 15 分钟;Antigravity 有两个池，不按这条处理。收到过 hook 事件的服务以 hook 为准，没有的仍走日志监听。hook 报使用中后 15 分钟（agy 90 秒）既没有新事件也没有日志写入就当作已停（CLI 崩溃时不会触发结束 hook）。agy 没有审批事件。Codex 要在它的 `/hooks` 里信任新 hook 后才执行。Gemini、Grok Bot 是 app，没有 hook，仍按额度变化呼吸。

## 3. Popover 总览

- 点击菜单栏图标弹出宽 340pt 的窗口。
- 顺序：Codex → Claude → Grok（每个服务一个 block，用 Divider 分隔）。
- Header 一行：标题「Usage / 用量」+ 副标题（最近一次刷新相对时间）+ 状态点（live / stale / offline）+ 三个一级图标按钮（刷新 / 统计 / 设置）+ ⋯ kebab 菜单（退出）。
- 每个 block 字段：
  - 服务 tile + 服务名 + 副标题（Provider · Plan）。
  - 5 小时窗口：38pt 剩余百分比 + 进度条 + 重置倒计时 + 「今日 cost」+「本周 cost」。
  - 周窗口：缩小版进度条 + 百分比 + 重置时间。
  - Grok 用云端当前周期替代 5 小时窗口（周/月/日由服务端返回），不显示 5 小时条；每块下方显示最近刷新时间与刷新间隔。
  - 失败时下方两行内短文案提示。
  - Codex 新模型若尚未进入价格表，今日/本周费用显示为 `—`，不再伪装成 `$0`。
- 关闭两个服务时显示"未启用任何服务 / 到「设置 → 账号」开启"占位。
- 状态点阈值：以当前额度刷新间隔为基准，age ≤ 1.5× 间隔为 live，≤ 3× 为 stale，超过为 offline。

## 5. 自动后台刷新

- 后台两条独立循环：
  - 额度 API 循环：默认 2 分钟，可选「1m / 2m / 3m / 5m / 10m」。
  - 本地 JSONL 扫描循环：默认 2 分钟，可选「1m / 2m / 3m / 5m / 10m」。
- 端点：
  - Codex：`GET https://chatgpt.com/backend-api/wham/usage`，带 `ChatGPT-Account-Id` 头。
  - Claude：`GET https://api.anthropic.com/api/oauth/usage`，带 `anthropic-beta: oauth-2025-04-20`。
  - Grok：`GET https://cli-chat-proxy.grok.com/v1/billing?format=credits`，与 Grok CLI `/usage` 同一只读额度接口。
  - Gemini / agy：本机 `agy -p /usage --output-format json`（一次约 10–15 秒，同时得到两个池子）。定时刷新至少间隔 100 秒（默认跟随 2 分钟额度刷新），手动刷新不受此限；输出含 429 / RESOURCE_EXHAUSTED 时同样 10 分钟退避；失败保留已有快照。
  - Grok Bot：`POST https://api2.cursor.sh/aiserver.v1.DashboardService/GetSandUsageStatus`（token 取自 Grok Bot app 的加密登录，见 §1）。
- 限流策略：
  - 同一服务两次成功之间至少 60 秒，周期性触发若间隔不足直接跳过。
  - 收到 429 后该服务进入 10 分钟退避，期间所有请求短路。
  - 手动「立即刷新」可绕过 60s 节流但仍遵守 429 退避。
- Claude API 失败且**完全没有可展示缓存**时，手动刷新会触发一次 Claude CLI 兜底（启动 `claude` 进程，向其 stdin 写入 `/usage`，解析输出），CLI 兜底也有独立 10 分钟冷却。
- Token 续期：Codex / Claude 双方均在 access_token 距离过期 5 分钟内时用 refresh_token 自动续期，并把新 token 写回原存储位置（文件或 Keychain）。
- 启动行为：先读本地额度缓存让 UI 立刻有数；首次刷新由调度器节奏触发；网络失败保留已有快照，仅以小字提示。

  3. 每一天的每个服务只算一份：网站记下每个人每天传过哪几个服务和传了多少(`usage_uploads`,按日期 × 服务，量是 token 总数，Gemini 是回答次数);再传同一天同一个服务，量更多才整份换成新的(筹码跟着重算)，一样多或更少就跳过。本机也按（日期, 服务）打标签(`web-uploads-<用户名>.json`)、记下网站上的量(启动、连上、每次上传前从网站拉一次):没标签的传，有标签但本机这一天的量比网站上多的也传。2026-10-29 起：以前一天传过就再也不收，后来才找到的会话(比如新加了一个 Codex 目录，里面是另一个账号以前的会话;或者传过之后才落盘的日志)补不上去，那几天只算了传的时候本机有的那部分;现在这些天会在下次上传时补齐。2026-10-23 以前只按日期记，那时传过的日子当作 Codex / Claude / Grok 都传过了，Grok Bot、Antigravity、Gemini 还能补传。所以重复点、重装、换台电脑都不会叠加筹码(几台电脑各有一部分时取量最多的那份)。
  4. 自动上传(默认关，开关写「每天 0:30 上传」)：每天 0:30 先扫一遍本地统计，再把没标签的天传上去(前一天刚过完;2026-10-29 前是中午 12:00);0:30 时 Mac 在睡眠或没开 App，醒来 / 下次启动扫描完补传。一天只自动传一次，没传成功(断网等)下次扫描完再试。(2026-10-23 起;以前是每次扫描完都传、前一天过零点 1 小时后才传。)
  5. 一键上传：每天只能成功点一次，点过当天变灰;断网等没传成功时可以再点。自动上传不占这一次。
  6. 网站不再认令牌(401)时自动断开，提示重新连接;其他失败保留标签和设置，下次再传。
  7. 订阅(2026-10-28 起):网站个人主页 @用户名后面显示各服务账号的套餐(服务的标 + 套餐，同一套餐几个账号写「×n」,同一服务里高档在前，免费的灰色排最后)。ChatGPT 的 Pro 分 Pro Lite / Pro 20x / Pro Max(Codex 登录里的套餐代号 prolite / pro / promax;App 和网站上 pro 都写成 Pro 20x),Claude 的 Max 分两档(凭据或资料接口的 rateLimitTier,max_5x / max_20x,2026-10-31 起显示成 Max / Ultra)。订阅随用量一起上传：每次上传(一键 / 自动，不管有没有新的天)把 App 里启用着的账号(本机账号看服务开关，其他账号看它那一行的「启用」)的套餐传上去(`PUT /api/v1/accounts`):一个账号一条，只传服务、套餐和账号摘要(「服务:账号」的 SHA-256 前 16 位),不传邮箱;Gemini App 和 Antigravity 是同一份 Google 订阅，记成 Gemini、同一个 Google 账号只算一次。没传成功不影响用量上传，下次上传再传。网站按设备整份替换(App 带上这台电脑固定的设备 id,重新连接网站换了令牌也替换这台设备上次传的;2026-10-29 前按令牌替换，重新连接后旧令牌传过的旧订阅——比如早就退订的 Claude Pro——会一直留在主页上，新版第一次上传时清掉),几台设备之间按账号摘要去重，90 天没再上传的设备不算。网站成就里的 Claude Pro / Claude Max / GPT Plus / GPT Pro 按这份订阅解锁。

## 7. 主窗口 — 统计

- 统计 · 概览：
  - 顶部工具栏：时间范围 segmented（今天 / 昨日 / 7 天 / 30 天 / 全部 / 自定义）+ 服务筛选按钮（全部 / Codex / Claude / Grok）。「全部」包含已启用的 Grok Bot / Gemini / agy；单独筛选按钮暂只有原三家。

  - KPI 3 张：估算费用、Tokens（不含缓存读取）、缓存读取（附占全部 Token 百分比）。前两张带相对上一同长度区间的环比（中性灰，>999% 封顶），「全部」时底部有按服务拆分的细条（含新服务的识别色）。
  - 每日用量：堆叠细柱 + 日均虚线，可切换 费用 / Tokens，悬停显示当日各服务数值。日均数值写在标题「每日用量」旁(一小段虚线 +「日均 $X」，和图里的虚线对应)，不再标在图里——范围长时柱子密，图内标注会压在柱子上(2026-10-22)。右上角服务图例放得下就写名字，窗口窄时只留图标(悬停看名字)，不折行。横轴约 6 个日期标签，从最后一天往前每 N 天一个，标签正对它那天的柱子(2026-10-22 修正：以前居中到 N 天区间里，偏后两天多)。切换时间范围、自定义日期或服务筛选时，柱子和日均线从底部弹簧长出来(约 0.5 秒，纵轴刻度固定在最终值，不跟着缩放)。

## 13. 风险 / 待持续关注

1. **非公开接口稳定性**：`wham/usage` / `oauth/usage` 字段可能随时调整，解析器需要保持容错。
2. **Keychain 弹窗**：首次读 `Claude Code-credentials` 系统会弹一次授权窗，引导文案已加。
3. **价格表漂移**：当前对齐 cc-switch / CodexBar 2026 上半年价位；模型迭代后需要同步。
4. **JSONL 量级**：长期使用后 `~/.claude/projects` 可达数百 MB；增量 watermark + seen ID 上限保证启动 / 扫描时间可控，但 seen 集合上限 20000 时若历史窗口超过该长度会有边缘重复风险。
5. **签名与公证**：发布前需 Apple Developer 证书；当前开发期未签名，README 标注「右键打开」。

### Claude 云端 Projects 用量（2026-10）

- 设置 → 刷新提供「同步云端用量」，默认关闭，复用当前本机 Claude Code 账号。首次同步回补本地昨天 00:00 起的记录，此后保留历史；正常至少间隔 5 分钟（跟随日志扫描触发），429 至少退避 10 分钟且遵守更长的 Retry-After。
- 仅接入 Projects beta 的 anthropic_cloud 会话（项目主会话和子任务）；Remote Control / bridge 仍由本机日志统计。普通 claude.ai 聊天不在范围内。
- Token 包含输入、输出、缓存读取和缓存写入。以服务端每轮 result 的累计用量差值统计，按结束日期归档，不按剩余额度倒推。跨午夜的一轮归入结束当天。费用采用服务端估算费用，用户自定义价格优先，不代表订阅实际扣款。
- 同一 message.id 同时存在云端和本机时，从合并统计中扣除已计的本地贡献。重复同步、重启、价格重算不能再次叠加云端历史。
- 错误保留已恢复数据并显示同步状态。只能恢复接口仍提供的会话；已删除、不可见或被截断的历史不补造。
